# Decisions

## 2026-08-08 (게임 제목 = Meowdel)

- 플레이어에게 보이는 게임 제목·브랜드를 **Meowdel**로 통일한다 (메뉴/HUD/페이지 title/README/기획 PDF 표기).
- 세이브 키·npm 패키지명(`ai-factory`)은 호환을 위해 유지한다.

## 2026-08-08 (기획서 = 구현 재동기화)

- `기획서/01~05`, 크레딧 업그레이드 PDF, 소개 PDF를 **현재 빌드** 기준으로 재작성.
- 반영: 맵 960×580, 왼쪽 세로 선반·하단 생산 라인, 납품 +100/+50/+20/0, 준비 타임 전용 상점, 업그레이드 전체 해금, 분석기 Z 닫기.
- 폐기: 인게임 터미널(E/Space), 납품 reward×0.35, 하단 선반·중앙 라인·960×720, 업그레이드 라운드 해금 게이트.

## 2026-08-08 (업그레이드 전체 해금 + 휴대 아이템 최상위 표시)

- 공장 업그레이드는 라운드 클리어 게이트 없이 **처음부터 전부 구매 가능** (잔액·최대 레벨만 검사).
- 손에 든 주문서/칩/사진은 플레이어 스프라이트보다 **항상 위**에 그린다 (위로 볼 때 뒤로 보내던 처리 제거).

## 2026-08-08 (준비 타임 = 업그레이드 구매 전용)

- 업그레이드 구매는 **라운드 시작 전 준비 타임**에서만 한다. 주방 인게임 터미널은 제거.
- 흐름: 정산 → 준비 타임(상점) → 라운드 시작. 이어서 하기도 준비 타임을 먼저 연다.
- 새 게임(r00 튜토리얼)은 준비 타임을 건너뛰고 바로 시작한다.

## 2026-08-08 (크레딧 & 공장 업그레이드)

- 납품 보상은 기획 표 고정: 성공 +100 / 완벽 +50 / 인내심≥50% +20 / 실패 +0. 라운드 정산 크레딧은 유지.
- 성장형 4종(작업화·장갑·커피·생산기)은 Lv.1~3, 기능형 3종(칩 선반·분석기·주문 분석기)은 1회 구매.
- 업그레이드는 세이브 `upgradeLevels`에 유지하고, **새 게임** 시 `createDefault`로 초기화.
- 조작키는 기획서 E/Space 대신 기존 **Z**로 통일. 분석 UI는 칩 이름을 노출하지 않는다.

## 2026-08-07 (기획서 = 구현 동기화)

- `기획서/01~05`를 **현재 플레이 가능한 빌드** 기준으로 재작성한다. 구버전의 포트 드래그 DAG·캐릭터 미조작·장치 배치 중심 서술은 폐기한다.
- 장르 고정: Overcooked형 WASD 운반 + 모듈 칩 슬롯 + VRAM 소프트 제약 + r00 단계 잠금 튜토리얼.
- PDF는 `Docs/_tools/generate_plans.py`로 재생성한다 (Linux: WenQuanYi Micro Hei).

## 2026-08-07 (실습형 튜토리얼 r00)

- 새 게임은 `r00`부터. `isTutorial`이면 인내심 감소/이탈 없음.
- 단계 잠금은 `TutorialGuide`가 담당하고 `KitchenSession` 핵심 규칙은 최소 확장만 한다.

## 2026-08-05 (플레이어 고양이 스프라이트)

- 플레이어는 `public/assets/characters/PlayerAnim/`의 32×32 시트를 사용한다.
- Idle 4프레임 / Walk 2프레임, 운반 시 Handle Idle·Walk로 전환한다.
- 시트 검정 배경은 투명으로 전처리하고, Phaser nearest 필터로 픽셀을 유지한다.

## 2026-08-04 (라운드 VRAM 예산 = 최적 파이프라인)

- 각 라운드 `vramBudget`은 해당 라운드 손님 큐의 **이론 최소 VRAM(ideal)** 이상이 되도록 맞춘다.
- 최적 칩만 쓰면 예산을 초과하지 않고, 불필요 칩을 꽂을 때만 초과·슬로우다운·예산 점수 감소가 난다.
- 현재 값: R1 24 / R2 44 / R3 42 / R4 55 / R5 61 / R6 74. 큐 생성은 `buildRoundOrderQueue`를 세션·테스트가 공유한다.

## 2026-08-04 (프롬프트 다양화 + 슬롯 스왑)

- 손님 프롬프트는 칩 이름·정답 키워드를 직설하지 않는 **우회 문구**로 다양화한다. 평가는 기존 `requiredTags`/점수 규칙을 유지한다.
- 주문 튜토리얼도 정답 칩을 직접 말하지 않고, 해금 위젯(`unlockTutorial`)으로 모듈 학습을 맡긴다.
- 모듈 칩을 든 채 찬 슬롯에 `Z`하면 손↔슬롯을 **스왑**한다. 같은 칩이면 거부한다.

## 2026-08-03 (손님 머리 위 프롬프트)

- 손님 요청 문구는 카운터 머리 위에 **한 줄 말풍선**으로 보여 준다. 주문서를 집으면(`orderTaken`) 숨긴다.
- 긴 프롬프트는 말줄임 처리하고, 들고 있는 주문서의 X 들여다보기는 그대로 유지한다.

## 2026-08-03 (모듈 해금 튜토리얼)

- 라운드 시작 시 아직 소개하지 않은 해금 칩이 있으면 **중앙 블로킹 모달**로 설명한다 (Phaser pause).
- 문구 형식: `이건 ~~한 모듈입니다.` (`ModuleDefinition.unlockTutorial`)
- `introducedModuleIds`를 세이브에 저장해 같은 모듈 설명을 반복하지 않는다. 기존 v2 세이브는 빈 배열로 호환.
- r00 튜토리얼 라운드에서는 모달을 띄우지 않고 모듈을 자동 introduced 처리한다.

## 2026-08-03 (시뮬 프리뷰 강화)

- 실제 LLM/이미지 API는 쓰지 않는다. 칩 태그·품질 점수 기반 **절차적 CSS 프리뷰**를 강화한다.
- `previewKey`에 품질 밴드(`lo|mid|hi`)를 포함해 같은 태그라도 점수에 따라 노이즈·선명도가 달라지게 한다.
- 들여다보기(X)에서 적용 효과 목록과 주제/스타일/구도/선명 점수를 함께 보여 주문서↔결과 비교를 돕는다.

## 2026-08-02 (바닥 내려놓기)

- 주변에 스테이션/손님이 없을 때 `Z`로 들고 있는 주문서·모듈 칩·이미지를 바닥에 내려놓을 수 있다.
- 손이 비어 있을 때만 바닥 물건을 상호작용 대상으로 잡는다(들고 있을 때는 근처 바닥 물건이 있어도 내려놓기 가능).
- 손님이 이탈하면 그 손님의 주문서/이미지가 바닥에 있어도 함께 제거한다. 모듈 칩은 유지.

## 2026-07-31 (라운드·VRAM·효율 점수)

- 플레이를 **라운드 단위**(r00 튜토리얼 + R01~R06)로 운영한다. 라운드마다 목표 손님 수가 고정된다.
- VRAM은 **소프트 제약(1B)**: 예산 초과해도 생산 가능, 대신 생산 속도 저하 + 정산 점수 감소.
- VRAM은 **생산마다 소모(2B)**: 슬롯 칩 cost 합을 누적하고, 라운드 종료 시 리셋.
- 라운드 종료 시 납품 성공률·VRAM 효율·이탈·예산 준수로 100점 환산 후 S~D 등급과 크레딧을 지급한다.
- 저장 스키마를 `version: 2` (`activeRoundId`, `completedRoundIds`, `bestRoundScores`)로 올린다.

## 2026-07-30 (Overcooked 개편)

- 공장 그래프(포트 드래그 DAG) 플레이를 **폐기**하고, **1A + 2B**로 전환한다.
  - 1A: WASD 캐릭터 + **Z** 상호작용으로 주문서/칩/이미지를 운반한다. (초기안 E는 Z로 확정)
  - 2B: 모듈은 선반 칩을 집어 입력~출구 사이 슬롯에 꽂는다.
- 입력기·출구는 스테이션이며 칩이 아니다. 플레이어가 꽂는 것은 중간 모듈(+ 그림 제작기)이다.
- 손님이 프롬프트를 가져오고, 플레이어가 이미지를 다시 전달하는 것이 핵심 루프다.
- 동시 손님은 MVP에서 최대 2명, 인내심 바를 표시한다.
- 결정적 `GenerationSimulator` / `OrderEvaluator`와 O01~O06 데이터는 유지한다.
