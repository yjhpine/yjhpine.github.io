## 적용한 기획

- 장르: **주문 폭주형 파이프라인 팩토리** (Overcooked의 손님·시한 감정 + Factorio/Shapez의 라인 구축).
- 핵심 루프: 손님 도착 → 주문 확인 → **중간 장치** 구축/조정 → 생산 → **주문서↔결과 비교** → 문제 수정 → 납품 → 다음 손님.
- 주문서 입력기·배송대는 기본 고정. 플레이어는 중간 모듈만 구성한다.
- MVP는 초보자용 게임 용어, 포트 연결, 주문서↔결과 비교, 결정적 결과와 행동형 피드백을 우선한다.
- 대기열·시한 폭주는 O01~O06 검증 후 확장한다. 캐릭터 액션형 오버쿡드는 채택하지 않는다.
- 실제 AI 실행, ComfyUI, 서버, VRAM 상세 경제, 자동화 분기·재처리는 제외한다.

## 첫 수직 슬라이스와 콘텐츠

첫 수직 슬라이스는 O01에서 주문서 입력기 → 그림 제작기 → 배송대를 연결하고, 생산·납품·보상을 완료하는 흐름이다. 이후 O02~O06에서 스타일, 금지 목록, 구도, 선명화, 품질 검사와 **비교 읽기**를 해금한다. 다음 확장은 O07~O08 대기열·완화 타이머다.

## 구조와 순서

1. Vite/Phaser/TypeScript/Vitest 기반을 만든다.
2. 순수 TypeScript 공장 그래프와 파이프라인 계산을 구현하고 테스트한다.
3. Phaser에는 배치 공간·장치·포트·연결·카메라만 맡기고, HTML에는 메뉴·패널·결과를 맡긴다.
4. localStorage 저장과 6개 의뢰 진행을 연결한다.
5. typecheck/test/build 뒤 GitHub Actions가 `dist/`를 Pages에 배포한다.

## 기술 위험과 대응

- WebGL 대신 정적 Phaser/Vite를 사용해 설치·유료 라이선스·네이티브 플러그인 위험을 없앤다.
- 외부 이미지가 없어도 결과 차이가 보이도록 CSS 도형, 색상, 모자, 위치, 흐림, 상태 배지를 조합한다.
- Pages 하위 경로 문제는 Vite base를 저장소 이름에서 계산해 방지한다.
